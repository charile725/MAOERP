# 一番賞特殊機制邏輯說明

# 一、最後賞（Last Prize）

## 設計概念

最後賞是一番賞的可選特殊獎品，當最後一抽被抽出時送出。

**核心規則：不計入抽數，但算成本。**

這代表最後賞會拉高每抽均價（`avgCost = totalCost / totalDraws`），因為分母不變但分子增加了。

---

## 資料結構

```
ichiban_kuji 表
├── last_prize_name         TEXT (nullable)  — 官方套用：存名稱字串
└── last_prize_product_id   UUID (nullable)  — 自組套用：關聯到 products 表
```

**Schema 定義** (`lib/schemas.ts:139-141`)

```typescript
// 最後賞（不計入抽數，但算成本）
last_prize_name: z.string().optional().nullable(),
last_prize_product_id: z.string().uuid().optional().nullable(),
```

官方套 vs 自組套的差異：
| | 官方套 | 自組套 |
|---|---|---|
| `last_prize_name` | 填入名稱 | 可填可不填 |
| `last_prize_product_id` | **永遠 null** | 關聯商品 UUID |
| 成本計算方式 | 已含在 `total_cost` 中 | 從商品的 `cost` 欄位取得 |

## 建立 / 更新一番賞時的成本計算

### API 建立 (`app/api/ichiban-kuji/route.ts:134-175`)

```typescript
let totalDraws = 0
let totalCost = 0
let lastPrizeCost = 0

if (isOfficial) {
  // 官方套：成本來自使用者輸入，最後賞成本已包含在 total_cost 中
  totalDraws = draft.prizes.reduce((sum, p) => sum + p.quantity, 0)
  totalCost = draft.total_cost || 0
} else {
  // 自製套：成本從各商品計算
  const productIds = draft.prizes.map(p => p.product_id).filter(Boolean)

  // 加入最後賞商品ID（如果有）
  if (draft.last_prize_product_id) {
    productIds.push(draft.last_prize_product_id)
  }

  // 批次查詢所有商品成本
  const productCostMap = new Map(products.map(p => [p.id, p.cost]))

  for (const prize of draft.prizes) {
    const cost = productCostMap.get(prize.product_id) || 0
    totalDraws += prize.quantity        // ← 最後賞不在 prizes 裡，所以不會被加
    totalCost += cost * prize.quantity
  }

  // 加入最後賞成本（不計入抽數）
  if (draft.last_prize_product_id) {
    lastPrizeCost = productCostMap.get(draft.last_prize_product_id) || 0
    totalCost += lastPrizeCost           // ← 只加成本，不加抽數
  }
}

const avgCost = totalDraws > 0 ? totalCost / totalDraws : 0
```

## 廢套結算（Close-Set）

`app/api/ichiban-kuji/[id]/close-set/route.ts`

### 用途

當自製一番賞要提前結束（還沒抽完就廢套），計算「實際被抽走的商品成本」vs「POS 已記錄的成本」之間的差額，建立費用記錄做調帳。

### API 參數

```typescript
POST /api/ichiban-kuji/:id/close-set

Body:
  preview: boolean           — true 時只回傳計算結果，不寫入
  account_id?: string        — 選填，要扣款的帳戶
  last_prize_delivered?: boolean  — 最後賞是否已送出（影響成本計算）
```

### 驗證規則

```typescript
// 僅自製套可進行廢套結算
if (kuji.set_type !== 'custom') → 錯誤

// 必須是啟用中
if (!kuji.is_active) → 錯誤
```

### 計算流程（8 個步驟）

```
步驟 1：讀取一番賞及所有賞項（含商品成本）
步驟 2：計算各獎品的已抽數量及成本
步驟 3：最後賞成本（條件性加入）
步驟 4：已記錄成本 = avg_cost × 已賣總抽數
步驟 5：差額 = 實際成本 - 已記錄成本
步驟 6：建立 expense 費用記錄
步驟 7：更新帳戶餘額
步驟 8：停用一番賞
```

### 步驟 2：計算已抽商品實際成本 (`close-set/route.ts:77-106`)

```typescript
let totalDrawsSold = 0
let actualCostOfDrawn = 0

for (const prize of prizes) {
  const drawn = prize.quantity - prize.remaining   // 已抽 = 總數 - 剩餘
  const unitCost = prize.products?.cost || 0
  const drawnCost = drawn * unitCost
  totalDrawsSold += drawn
  actualCostOfDrawn += drawnCost
}
```

### 步驟 3：最後賞成本（條件性加入）(`close-set/route.ts:108-123`)

```typescript
let lastPrizeCost = 0
let lastPrizeProductName = null

if (lastPrizeDelivered && kuji.last_prize_product_id) {
  // 查最後賞商品
  const { data: lastProduct } = await supabaseServer
    .from('products')
    .select('id, name, cost')
    .eq('id', kuji.last_prize_product_id)
    .single()

  if (lastProduct) {
    lastPrizeCost = lastProduct.cost || 0
    lastPrizeProductName = lastProduct.name
    actualCostOfDrawn += lastPrizeCost    // ← 加入實際成本
  }
}
```

**重點：** 只有勾選「最後賞已送出」才會把最後賞成本加入 `actualCostOfDrawn`。如果最後賞沒送出（例如套還沒抽到最後就廢了），就不計入。

### 步驟 4-5：差額計算 (`close-set/route.ts:125-129`)

```typescript
// 已記錄成本 = avg_cost × 已賣總抽數
// （POS 每次賣出一抽時，都用 avg_cost 記錄 COGS）
const recordedCost = kuji.avg_cost * totalDrawsSold

// 差額 = 實際 - 已記錄
const adjustment = actualCostOfDrawn - recordedCost
```

**為什麼會有差額？**

因為 POS 賣出每一抽時以均攤成本 `avg_cost` 記錄，但實際上每個賞品的成本不同。當套沒抽完就廢掉時，「被抽走的東西」和「均攤假設抽走的東西」會有落差。

舉例：
- A賞 成本 500，1 個
- B賞 成本 100，4 個
- 總成本 = 500 + 400 = 900，5 抽
- avg_cost = 900 / 5 = 180
- 假設只賣了 2 抽，剛好抽到 A賞 + 1個B賞
- 實際成本 = 500 + 100 = 600
- 已記錄成本 = 180 × 2 = 360
- 差額 = 600 - 360 = +240（需補記費用）

### 步驟 6：建立費用記錄 (`close-set/route.ts:177-197`)

```typescript

```

```

---
A賞 限定公仔: 已抽 1/1, 成本 800

...
```

### 步驟 7：更新帳戶餘額 (`close-set/route.ts:199-219`)

```typescript

  await updateAccountBalance({
    supabase: supabaseServer,
    accountId,
    amount: absAmount,
    direction: adjustmentAmount > 0 ? 'decrease' : 'increase',
    //         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
    //         差額為正（實際成本 > 已記錄）→ 扣減帳戶（多花了）

```

## 完整資料流程圖

```
建立一番賞
    │
    ├─ 官方套：last_prize_name = "XXX"
    │          last_prize_product_id = null
    │          成本已含在 total_cost 中
    │
    └─ 自組套：last_prize_product_id = UUID
              totalCost += product.cost（不加 totalDraws）
              avgCost = totalCost / totalDraws（均價被拉高）
    │
    ▼
POS 賣出每一抽
    │
    └─ COGS = avg_cost（均攤成本，含最後賞分攤）
    │
    ▼
廢套結算
    │
    ├─ 計算被抽走商品的「實際成本」
    │   └─ 如果最後賞已送出 → actualCostOfDrawn += lastPrizeCost
    │
    ├─ 計算 POS 已記錄的「均攤成本」= avg_cost × 已售抽數
    │
    ├─ 差額 = 實際 - 均攤
    │   ├─ > 0：補記費用（實際花更多）
    │   └─ < 0：沖回費用（實際花更少）
    │
    ├─ 建立 expense 記錄（類別：一番賞結損）
    ├─ 更新帳戶餘額
    └─ 停用一番賞（is_active = false）
```

# 二、開套優惠（Opening Combo Prices）

## 設計概念

開套優惠是「僅在整套完全未抽過時」才適用的特殊折扣。
用途：吸引第一位客人開套，例如「開套 3 抽 280 元」。

**核心規則：一旦有任何賞品被抽出，開套優惠立即失效，只剩一般套優惠。**

---

## 資料結構

```
ichiban_kuji 表
├── combo_prices            JSONB  — 一般套優惠（永遠可用）
└── opening_combo_prices    JSONB  — 開套優惠（僅限未開套）
```

兩者共用相同的 Schema 定義 (`lib/schemas.ts:124-126`)：

```typescript
export const ichibanKujiComboPriceSchema = z.object({
  draws: z.number().int().positive('Draws must be positive'),
  price: z.number().min(0, 'Price must be positive'),
})
```

每筆紀錄就是 `{ draws: 抽數, price: 價格 }`，例如 `{ draws: 3, price: 280 }` 代表「3 抽 280 元」。

### 一般套優惠 vs 開套優惠

| | `combo_prices` | `opening_combo_prices` |
|---|---|---|
| 可用時機 | 永遠可用 | 僅限整套完全未抽過 |
| 失效條件 | 無 | 任何賞品 `remaining < quantity` |
| UI 色系 | 灰色 | 琥珀色（amber） |
| 標籤 | 套優惠 | 開套優惠（僅限未開套） |

## POS 定價邏輯

`app/pos/page.tsx:685-728` / `app/pos-live/page.tsx:645-688`

### 步驟 1：合併優惠方案

```typescript
const regularCombos = group.kuji?.combo_prices || []
const openingCombos = isUntouched
  ? (group.kuji?.opening_combo_prices || [])  // 未開套 → 加入開套優惠
  : []                                         // 已開套 → 不加入
const comboPrices = [...regularCombos, ...openingCombos]
  .sort((a, b) => b.draws - a.draws)           // 按抽數從大到小排序
```

### 步驟 2：貪婪演算法分配價格

```typescript
let remaining = totalCount     // 客人這次要抽的總數
let totalComboPrice = 0
let comboDrawsUsed = 0

// 從最大組合開始匹配
for (const combo of comboPrices) {
  const sets = Math.floor(remaining / combo.draws)  // 可以用幾組
  if (sets > 0) {
    totalComboPrice += sets * combo.price
    comboDrawsUsed += sets * combo.draws
    remaining -= sets * combo.draws
  }
}

// 剩下不夠湊組合的，用原價
if (remaining > 0) {
  totalComboPrice += remaining * originalPrice
}
```

### 舉例

一番賞設定：
- 每抽原價 100 元
- 一般套優惠：5 抽 450 元
- 開套優惠：3 抽 250 元

**情境 A：整套未開過，客人買 8 抽**
```
可用方案：[5 抽 450, 3 抽 250]（兩者都可用）
→ 5 抽 × 1 組 = 450
→ 3 抽 × 1 組 = 250
→ 總價 700（原價 800，省 100）
```

**情境 B：已有人抽過，客人買 8 抽**
```
可用方案：[5 抽 450]（只有一般套優惠）
→ 5 抽 × 1 組 = 450
→ 剩 3 抽 × 100 = 300
→ 總價 750（原價 800，省 50）
```

## 完整狀態流程圖

```
建立一番賞
    │
    ├─ 設定 combo_prices:          [{ draws: 5, price: 450 }]
    └─ 設定 opening_combo_prices:  [{ draws: 3, price: 250 }]
    │
    ▼
POS 賣出（isUntouched 判定）
    │
    ├─ 全部 remaining === quantity（未開套）
    │   └─ 可用方案 = combo_prices + opening_combo_prices
    │      └─ 合併後按 draws 大到小排，貪婪匹配
    │
    └─ 有任何 remaining < quantity（已開套）
        └─ 可用方案 = combo_prices only
           └─ opening_combo_prices 不再適用
    │
    ▼
第一筆銷售完成
    │
    └─ 部分賞品 remaining 減少 → isUntouched = false
       └─ 之後所有交易都不再享有開套優惠
```
